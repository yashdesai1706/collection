5. INDEXES, CONSTRAINTS & DATA INTEGRITY
================================================================================

1. Collection 'users':
   - `_id`: Default unique clustered index.
   - `email`: Unique secondary index (`unique: true`). Prevents duplicate customer accounts.

2. Collection 'products':
   - `_id`: Default unique clustered index.
   - `slug`: Unique secondary index (`unique: true`). Guarantees clean, clash-free SEO URLs
     for single product pages (/product/[slug]).

3. Collection 'orders':
   - `_id`: Default unique clustered index.
   - `user`: Foreign key reference to User model. Used by `/api/orders/myorders`.
   - `orderItems[].product`: Foreign key reference to Product model.

6. MONGOOSE MIDDLEWARE & CUSTOM METHODS
================================================================================

User Model (backend/models/User.js):
-----------------------------------
1. Pre-Save Middleware Hook (`userSchema.pre('save')`):
   - Automatically executes before saving a User document.
   - Checks if the `password` field was modified (`this.isModified('password')`).
   - If modified or newly created, generates a bcrypt salt with 10 rounds and hashes
     the plaintext password before writing to MongoDB.

2. Instance Method (`userSchema.methods.matchPassword`):
   - Signature: `async matchPassword(enteredPassword: string): Promise<boolean>`
   - Compares an incoming plain-text login password against the hashed password stored
     in the document using `bcrypt.compare()`. Returns true if valid.
